# Отчёт о выполнении проекта «План изучения SQL»

## 1. С какой задачей работал?

Создание детализированного пошагового плана изучения SQL с нуля до уровня Middle, а также его публикация в репозитории на GitHub.

В рамках задачи было выполнено:

- Настроена связь локального git-репозитория с аккаунтом GitHub (`mojohead-ai`) и репозиторием `-SQL`.
- Проанализированы три варианта промпта для генерации плана (плохой, средний, отличный), разобраны их сильные и слабые стороны.
- Через ИИ-агента (Claude Sonnet 4) сгенерирован основной документ `План_изучения_SQL.md` — курс на 8 недель с теорией, практическими заданиями и контролем усвоения.
- Созданы практические файлы `practise/week1.sql` … `week8.sql` — по 3 задания на неделю для вымышленной базы данных интернет-магазина.
- Все файлы закоммичены и запушены в GitHub (ветка `main`, коммит `726b1b9`).

## 3. Какие ошибки допустил ИИ-агент?

Работа шла через связку opencode + провайдер VseGPT. В процессе было выявлено несколько ошибок и проблем:

1. **Модель недоступна (`ProviderModelNotFoundError`).** Провайдер `vsegpt` был описан в конфиге только полем `api` без `npm` и списка моделей. Так как VseGPT нет в каталоге models.dev, opencode не знал модели провайдера и считал Sonnet недоступной.
2. **Отсутствие API-ключа в окружении.** Конфиг брал ключ из переменной `VSEGPT_API_KEY`, которая не была установлена. Приложение не подхватывало её даже после установки — пришлось вписать ключ напрямую в конфиг.
3. **Превышение лимита стоимости запроса.** VseGPT отклонял запросы (`Exceeded soft user limit per query`), т.к. ожидаемая цена одного запроса (~14.6) превышала лимит аккаунта (10). Решено снижением лимита вывода модели (`limit.output = 8000`).
4. **Неполное выполнение задания агентом.** Sonnet создал только основной файл плана, а папку `practise` не создал. При повторной попытке создал лишь `week1.sql`. Остальные файлы пришлось доделать вручную.
5. **Кодировка пути.** В логах и выводе PowerShell русскоязычные пути отображались некорректно (кракозябры), что затрудняло диагностику.

## 4. Что бы ты изменил в следующем запросе?

1. **Уточнить СУБД.** В промпте не указана целевая СУБД (MySQL/PostgreSQL). Синтаксис в заданиях местами различается — лучше сразу зафиксировать одну.
2. **Разделить задачу на этапы.** Вместо одного большого запроса (план + практика) — разбить на отдельные подзадачи: сначала план, затем практические файлы. Агент выполнил только часть первого запроса.
3. **Требовать полный результат.** Добавить в промпт явное требование «создай ВСЕ файлы и перечисли их список в конце» — это уменьшает риск неполного выполнения.
4. **Проверять выполнение.** Включить в запрос пункт о самопроверке агентом созданных файлов перед завершением.
5. **Зафиксировать формат схемы БД.** Схема базы дана в `week1.sql` и в основном плане — желательно описать её один раз и ссылаться, чтобы избежать расхождений.
6. **Задать уровень детализации практики.** Указать, что каждое задание должно быть самодостаточным (описание, ожидаемый результат, подсказка).
